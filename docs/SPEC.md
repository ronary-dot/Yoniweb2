אפליקציית Web חכמה לניהול תקציב בשני מצבים: **משפחה** ו**עסק**.

## 1. חזון ומטרות

**חזון:** מקום אחד, שקט ונקי, שבו אפשר לראות בשנייה "איפה אני עומד" — גם בבית וגם בעסק — בלי לעבור בין אפליקציות ובלי טבלאות אקסל.

**מטרות המוצר**

1. רישום הוצאה/הכנסה בפחות מ-5 שניות (3 הקשות לכל היותר מהמסך הראשי).
2. מעבר בין מצב משפחה למצב עסק ללא טעינה, ללא איבוד הקשר, ובתחושה של אותה אפליקציה.
3. תשובה מיידית לשלוש שאלות בכל מצב: *כמה נשאר החודש? לאן הלך הכסף? האם אני בדרך ליעד?*
4. דמו חי שאפשר להתנסות בו מהשנייה הראשונה, בלי הרשמה.
5. פריסה ל-Vercel בלחיצה אחת, ללא משתני סביבה חובה בשלב הראשון.

**לא-מטרות (בגרסה הראשונה)**

- חיבור לבנקים / Open Banking.
- הנהלת חשבונות מלאה, הפקת חשבוניות מס, דיווח למע״מ.
- ריבוי משתמשים בזמן אמת (משפחה עם כמה חשבונות) — מתוכנן לשלב 3.

## 3. מושג-העל: שני מצבים, אפליקציה אחת

### 3.1 מודל

- כל רשומה (תנועה, קטגוריה, יעד, לקוח) שייכת ל**סביבת עבודה** (`Workspace`) אחת.
- לכל משתמש יש בדיוק שתי סביבות בגרסה 1: `family` ו-`business`.
- המצב הפעיל נשמר ב-URL (`/family/...` או `/business/...`) — כך שקישור, רענון וכפתור "אחורה" תמיד עובדים.
- הניווט, מבנה המסך והרכיבים זהים; משתנים רק: צבע הדגשה, תוויות, מדדי הדשבורד ומסכים ייעודיים.

### 3.2 מתג המצבים (Mode Switch)

רכיב Segmented Control בראש הסרגל הצדדי (דסקטופ) / בכותרת העליונה (מובייל):

```
┌──────────────────────────┐
│  [ 🏠 משפחה ] [ 💼 עסק ]  │   ← "גלולה" פעילה מחליקה בין האפשרויות
└──────────────────────────┘
```

**התנהגות**

| פעולה | תוצאה |
| --- | --- |
| לחיצה על המצב השני | הגלולה מחליקה (spring, `duration: 0.35, bounce: 0`), צבע ההדגשה מתחלף, תוכן הדף עושה crossfade קצר |
| קיצור מקלדת `⌘/Ctrl + .` | מעבר מיידי — **ללא אנימציה כלל** (פעולת מקלדת חוזרת; לפי עקרון "Never animate keyboard-initiated actions") |
| מעבר מצב | שומר את סוג הדף: אם הייתי ב"תנועות" במשפחה — אגיע ל"תנועות" בעסק |
| מסך ייעודי שאין לו מקביל (למשל "לקוחות") | נוחת בדשבורד של המצב השני |

**פירוט האנימציה (מעבר בלחיצה)**

1. הגלולה: `transform: translateX()` בלבד, spring קריטי (ללא קפיצה — זה כלי פיננסי, לא משחק).
2. צבע הדגשה: משתנה CSS `--accent` על `<html data-mode>`; מעבר `color/background-color 200ms ease`.
3. תוכן: יציאה `opacity 1→0` + `filter: blur(0→2px)` ב-120ms, כניסה `opacity 0→1` + `blur(2px→0)` + `translateY(4px→0)` ב-200ms `var(--ease-out)`. ה-blur מגשר על ה-crossfade כך שהעין רואה מעבר אחד ולא שני מסכים חופפים.
4. מספרי הדשבורד: NumberFlow מגלגל את הספרות מהערך הקודם לחדש (רק כשהרכיב נשאר על המסך).
5. `prefers-reduced-motion`: ללא translate/blur; נשאר fade של 150ms בלבד.

### 3.3 זהות חזותית לכל מצב

| | משפחה | עסק |
| --- | --- | --- |
| צבע הדגשה | ירוק-מרווה חם (`oklch(0.62 0.12 160)`) | כחול-דיו (`oklch(0.55 0.14 255)`) |
| טון כללי | רך, מעוגל יותר בכרטיסי יעדים | חד, צפוף יותר בטבלאות |
| שפה | "הוצאות הבית", "חיסכון משפחתי" | "תזרים", "לקוחות", "הוצאות תפעול" |
| מדד ראשי | נשאר לחודש | מזומן צפוי בעוד 30/60/90 יום |

ההבדל צריך להיות מורגש אבל עדין — אותה טיפוגרפיה, אותם רדיוסים, אותם רווחים. רק הצבע והתוכן מספרים איפה אני.

## 4. ארכיטקטורת מידע ומסכים

### 4.1 מפת ניווט

```
/                         → הפניה למצב האחרון (ברירת מחדל: /family)
/welcome                  → מסך פתיחה: "התחל ריק" / "טען נתוני דמו"
/[mode]                   → דשבורד
/[mode]/transactions      → תנועות (רשימה, חיפוש, סינון)
/[mode]/budgets           → תקציבים לפי קטגוריה
/[mode]/goals             → יעדים (משפחה: חיסכון; עסק: יעדי הכנסה/רזרבה)
/[mode]/reports           → דוחות וגרפים
/business/clients         → לקוחות וחובות פתוחים (עסק בלבד)
/business/cashflow        → תחזית תזרים (עסק בלבד)
/family/activities        → חוגים ופעילויות ילדים (משפחה בלבד)
/family/shopping          → רשימות קניות ומעקב סופר (משפחה בלבד)
/settings                 → הגדרות, קטגוריות, ייבוא/ייצוא, ניהול דמו
```

### 4.2 מבנה מסך כללי

**דסקטופ (≥1024px):** סרגל צד ימני (RTL) ברוחב 248px — מתג מצבים, ניווט, כפתור "+ תנועה חדשה". תוכן ברוחב מקסימלי 1120px.

**מובייל (<768px):** כותרת עליונה עם מתג מצבים קומפקטי; סרגל ניווט תחתון (5 פריטים: דשבורד, תנועות, ➕, יעדים, עוד); כפתור ➕ מרכזי פותח Drawer תחתון (Vaul).

### 4.3 פעולות גלובליות

| פעולה | איך |
| --- | --- |
| הוספת תנועה | כפתור ➕ / קיצור `N` → Dialog בדסקטופ, Drawer במובייל |
| חיפוש ופקודות | `⌘K` → Command palette (cmdk): "הוסף הוצאה 120 סופר", "עבור לעסק", "טען דמו" — נפתח **ללא אנימציה** |
| ביטול | כל מחיקה מציגה Toast (Sonner) עם "ביטול" ל-5 שניות במקום דיאלוג אישור |

## 5. פיצ'רים — מצב משפחה

### 5.1 דשבורד משפחה

1. **כרטיס "נשאר החודש"** — המספר הגדול במסך. מתחתיו פס התקדמות דק של התקציב החודשי, וטקסט: "₪1,240 לעוד 9 ימים · כ-₪138 ליום".
2. **הוצאות לפי קטגוריה** — רשימה אופקית של 5 הקטגוריות המובילות, כל אחת עם פס מילוי ביחס לתקציב שלה. חריגה = הפס בצבע אזהרה (לא אדום צועק — כתום עמום).
3. **יעדי חיסכון** — עד 3 כרטיסים עם טבעת התקדמות.
4. **חוגים השבוע** — מה מתוכנן ומה התשלום הבא.
5. **תנועות אחרונות** — 5 אחרונות, לחיצה פותחת עריכה.

### 5.2 מעקב הוצאות משק בית

- קטגוריות ברירת מחדל: סופר ומזון, דיור ושכירות, חשבונות (חשמל/מים/ארנונה/גז), תחבורה ודלק, ילדים וחינוך, חוגים, בריאות, ביגוד, בילויים ומסעדות, מתנות, ביטוחים, מנויים, שונות.
- אמצעי תשלום: אשראי, מזומן, העברה, ביט/פייבוקס, הוראת קבע.
- הוצאות קבועות (חודשיות/שנתיות) נוצרות אוטומטית בתחילת כל מחזור, מסומנות "צפויה" עד אישור.
- **"מחזור חודשי"** ניתן להגדרה (למשל מה-10 לחודש, לפי יום חיוב האשראי).

### 5.3 חוגים ופעילויות

- ישות `Activity`: שם הילד/ה, שם החוג, ספק, עלות, תדירות תשלום (חודשי/סמסטריאלי/שנתי), ימים ושעות.
- תצוגה: לפי ילד/ה, וסכום שנתי לכל ילד/ה.
- כל חוג מייצר תנועות צפויות בהתאם לתדירות.

### 5.4 קניות

- רשימות קניות פשוטות (פריט, כמות, סימון ✓). סימון פריט: קו חוצה שמתפשט מימין לשמאל (`clip-path` 180ms), והפריט יורד לתחתית הרשימה.
- "סגור קנייה": מזינים סכום סופי → נוצרת תנועה בקטגוריית סופר והרשימה מתאפסת.
- מעקב "ממוצע קנייה שבועית" ומגמה חודשית.

### 5.5 יעדי חיסכון משפחתיים

- יעד: שם, סכום יעד, תאריך יעד, אייקון/אמוג׳י, הפקדות.
- חישוב אוטומטי: "כדי להגיע בזמן — ₪650 בחודש".
- סטטוס: בדרך / מאחר / הושג.
- **השגת יעד** — הרגע היחיד באפליקציה עם "חגיגה": הטבעת נסגרת, אנימציית קונפטי עדינה וקצרה (≤1.2s), פעם אחת. נדיר → מותר להוסיף שמחה.

## 6. פיצ'רים — מצב עסק

### 6.1 דשבורד עסק

1. **מזומן זמין היום** — מספר ראשי.
2. **תחזית תזרים** — גרף שטח (recharts) ל-90 יום: קו בפועל + קו מקווקו צפוי. אזור מתחת לקו האפס צבוע בעדינות.
3. **כרטיסי KPI:** הכנסות החודש · הוצאות החודש · רווח תפעולי · חובות פתוחים של לקוחות.
4. **לקוחות שחייבים** — 5 החשבונות הפתוחים הגדולים, עם ימי איחור.
5. **הוצאות קבועות קרובות** — מה יורד ב-14 הימים הקרובים.

### 6.2 תזרים מזומנים

- כל תנועה עסקית היא `actual` (בוצעה) או `expected` (צפויה) עם תאריך צפוי.
- התחזית = יתרה נוכחית + הכנסות צפויות − הוצאות צפויות, מחושבת לפי יום.
- התראה רכה כשהתחזית יורדת מתחת ל"סף בטיחות" שהמשתמש קבע.
- תצוגת שבוע/חודש/רבעון; השוואה לתקופה המקבילה.
- "מה אם": מתג זמני לדחיית הכנסה/הוצאה צפויה ולראות מיד את ההשפעה על הגרף (הגרף עושה מעבר 250ms בין המצבים).

### 6.3 לקוחות והכנסות

- ישות `Client`: שם, איש קשר, תנאי תשלום (שוטף+30 וכו'), הערות.
- `Invoice` פנימית (לא חשבונית מס): מספר, לקוח, סכום, מע״מ (כן/לא), תאריך הפקה, תאריך פירעון, סטטוס (טיוטה / נשלחה / שולמה חלקית / שולמה / באיחור).
- סימון "שולם" יוצר אוטומטית תנועת הכנסה `actual`.
- דוח: הכנסה לפי לקוח, ממוצע ימי גבייה.

### 6.4 הוצאות תפעוליות

- קטגוריות ברירת מחדל: שכר ופרילנסרים, שכירות משרד, תוכנה ומנויים (SaaS), שיווק ופרסום, ציוד, רו״ח ויעוץ, נסיעות, ביטוח, עמלות בנק וסליקה, מסים ואגרות, שונות.
- הוצאות קבועות חוזרות + הוצאות חד-פעמיות.
- שדה "מוכר למס" (כן/לא/חלקי) — לסינון בלבד, ללא חישוב מס.

### 6.5 יעדים עסקיים

- יעד הכנסה חודשי/רבעוני.
- יעד "רזרבת ביטחון" (X חודשי הוצאות קבועות).

## 8. מצב דמו

### 8.1 דרישות

1. **כניסה ראשונה** (`/welcome`): שני כפתורים — "**טען נתוני דמו**" (ראשי) ו"התחל עם אפליקציה ריקה".
2. כפתור "טען נתוני דמו" זמין גם ב-`/settings` ובמצב ריק של כל מסך ("אין עדיין תנועות · טען נתוני דמו").
3. כשנתוני דמו טעונים — פס דק בראש המסך: "אתה צופה בנתוני דמו · אפס · נקה והתחל" (ניתן לסגירה).
4. "אפס דמו" מחזיר לנתונים ההתחלתיים; "נקה" מוחק הכל.
5. הדמו עובד **ללא שרת וללא הרשמה** — הנתונים נשמרים מקומית בדפדפן.
6. אפשרות קישור ישיר: `/?demo=1` טוען דמו אוטומטית (נוח לשיתוף).

### 8.2 תוכן נתוני הדמו

נוצר ע״י פונקציה דטרמיניסטית (`seed` קבוע) **יחסית לתאריך של היום**, כך שהדמו תמיד "עדכני": 6 חודשים אחורה + 3 חודשים קדימה של תנועות צפויות.

**משפחת כהן (משפחה):**
- 2 הורים, 3 ילדים (נועה 12, איתי 9, מאיה 5).
- הכנסה: 2 משכורות (₪14,500 + ₪11,200).

## 10. מערכת עיצוב

### 10.1 עקרונות (מתוך פילוסופיית Emil Kowalski)

1. **פרטים בלתי נראים מצטברים** — כל פרט קטן (מספרים טבלאיים, יישור, מצב לחיצה) נבנה נכון גם אם אף אחד לא ישים לב אליו.
2. **ריסון** — צבע אחד מדגיש לכל מצב, השאר גווני אפור ניטרליים. אין גרדיאנטים, אין צללים כבדים.
3. **צל במקום מסגרת** — כרטיסים עם צל שקוף-למחצה מרובד ומסגרת `1px` בשקיפות נמוכה, לא קו אפור מלא.
4. **ברירות מחדל טובות** — אין הגדרות שהמשתמש חייב לשנות כדי שהאפליקציה תיראה טוב.
5. **התנועה מתאימה לאופי** — דשבורד פיננסי = תנועות חדות ומהירות, כמעט בלי קפיצות.

## 11. מפרט תנועה ומיקרו-אנימציות

נבנה לפי מסגרת ההחלטה: *האם להנפיש בכלל → מטרה → easing → משך*.

| אינטראקציה | תדירות | החלטה | פירוט |
| --- | --- | --- | --- |
| לחיצה על כפתור / פריט | גבוהה | משוב לחיצה | `:active { transform: scale(0.97) }`, `transform 140ms var(--ease-out)` |
| Hover על שורה ברשימה | עשרות ביום | מינימלי | רק `background-color 150ms ease`, ומוגבל ל-`@media (hover:hover) and (pointer:fine)` |
| Command palette (`⌘K`) | מאות ביום | **ללא אנימציה** | פתיחה וסגירה מיידיות |
| קיצורי מקלדת (`N`, מעבר מצב) | גבוהה | **ללא אנימציה** | — |
| מתג מצבים (בלחיצה) | כמה פעמים ביום | מצב + רציפות מרחבית | ראה סעיף 3.2 |
| Dialog הוספת תנועה (דסקטופ) | כמה פעמים ביום | מניעת קפיצה | כניסה `opacity 0→1`, `scale(0.96→1)`, 200ms `--ease-out`, origin במרכז; יציאה 150ms (מהירה מהכניסה) |
| Drawer הוספת תנועה (מובייל) | כמה פעמים ביום | רציפות מרחבית + מחווה | Vaul: `translateY(100%)→0`, `--ease-drawer` 400ms, swipe-to-dismiss לפי מהירות (>0.11) ולא רק מרחק |
| Popover / Select / תפריט | כמה פעמים ביום | מניעת קפיצה | `scale(0.97→1)` + opacity, 160ms, `transform-origin: var(--transform-origin)` (מהטריגר) |
| Tooltip | עשרות | עדין | השהיה 400ms לראשון; tooltips צמודים נפתחים מיד ללא אנימציה |
| Toast (Sonner) | מזדמן | רציפות מרחבית | ברירת המחדל של Sonner — נכנס ויוצא מאותו כיוון |
| מספרים בדשבורד משתנים | מזדמן | הצגת שינוי | NumberFlow, ~500ms, רק כשהערך משתנה בזמן שהמשתמש מסתכל — לא בטעינה ראשונית |
| פסי תקציב / טבעות יעד | בטעינה | הסבר | מילוי `transform: scaleX()` מ-0 ל-ערך, 600ms `--ease-out`, פעם אחת בכניסה לדף, stagger 40ms |
| פריט חדש ברשימת תנועות | מזדמן | מניעת קפיצה | גובה + opacity (motion `layout`), 220ms |
| מחיקת פריט | מזדמן | מניעת קפיצה | יציאה `opacity→0` + `translateX(8px)` 150ms, ואז קריסת גובה; Toast עם "ביטול" |
| סימון פריט קנייה | עשרות | משוב | קו חוצה ב-`clip-path: inset()` 180ms |
| מעבר בין תצוגות גרף (שבוע/חודש) | מזדמן | מצב | crossfade 250ms + blur 2px |
| השגת יעד | נדיר | **הנאה** | טבעת נסגרת + קונפטי קצר, פעם אחת בלבד לכל יעד |
| טעינת דמו | פעם אחת | הנאה מתונה | stagger לפריטים הראשונים |
| מעבר בין דפים | גבוהה | **ללא אנימציה** של דף שלם | רק Skeleton אם יש המתנה >150ms |

**כללי ברזל**
- מנפישים רק `transform`, `opacity` (ו-`filter`/`clip-path` במקרים מוגדרים). אף פעם `width`, `height`, `top`, `margin` — חוץ מ-layout animations של motion ברשימות.
- אסור `transition: all`.
- אסור `ease-in` על UI.
- אסור `scale(0)` — מינימום `scale(0.95)` עם opacity.
- יציאה מהירה מכניסה.
- CSS transitions לכל מה שניתן להפריע לו (toggle, hover); motion רק ל-springs, layout ו-exit.
- ב-motion — `transform: "translateX(...)"` מלא ולא shorthand `x`, לרכיבים שמונפשים בזמן טעינת דף.
- `prefers-reduced-motion`: מבטלים תנועה מרחבית, משאירים fades קצרים ושינויי צבע.
- לפני כל merge של UI: הרצת סקיל `review-animations` על השינוי.

## 14. מובייל ותחושת "אפליקציה"

(לפי סקיל `mobile-native`)

- `viewport-fit=cover` + `env(safe-area-inset-*)` לסרגל התחתון ולכפתור ➕.
- גובה מסך עם `100dvh`, לא `100vh`.
- כל השדות ב-`font-size: 16px` לפחות — מונע זום אוטומטי ב-iOS.
- `-webkit-tap-highlight-color: transparent` + מצב `:active` משלנו.
- `touch-action: manipulation` על כפתורים (ללא השהיית הקשה כפולה).
- `user-select: none` על כפתורים ותוויות ניווט.
- `overscroll-behavior: contain` ב-Drawer ובגלילות פנימיות.
- `theme-color` תואם למצב ולערכת הצבעים.
- PWA: manifest + אייקונים → "הוסף למסך הבית" (שלב 2: offline עם service worker).
- בדיקה על מכשיר אמיתי (iPhone + Android) לפני כל שחרור.

## 15. נגישות

- עמידה ב-WCAG 2.2 AA; ניגודיות ≥4.5:1 לטקסט (כולל צבעי ההדגשה בשני המצבים ובמצב כהה).
- ניווט מלא במקלדת, focus ring נראה (`:focus-visible`, 2px בצבע ההדגשה).
- מתג המצבים = `role="radiogroup"` עם תוויות; הודעת `aria-live` "עברת למצב עסק".
- גרפים: טבלת נתונים חלופית מוסתרת ויזואלית + תיאור טקסטואלי.
- סכומים לא מסתמכים על צבע בלבד (סימן +/− ואייקון).
- `prefers-reduced-motion` ו-`prefers-color-scheme` מכובדים.
